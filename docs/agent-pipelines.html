Pi Agent Pipelines

This page documents the executable agents and pi-subagents chain pipelines stored in agents/. Diagrams are rendered with Mermaid in the browser.

Agent inventory

AAD owner/support agents

aad-slice-owner owns scoped work. aad-explorer, aad-reviewer, and aad-test-auditor provide read-only evidence, review, and verification audit support.

Hermes worker agents

tdd-coder implements scoped tasks, quinn-validator adversarially reviews diffs, and failure-classifier classifies failed attempts.

Browser automation

chrome-browser-agent uses the browser-chrome skill and MCP browser servers, defaulting to disposable headless Chrome unless profile/auth state is explicitly needed.

AAD discovery-to-plan chain

agents/aad-discovery-plan.chain.md turns a request into evidence first, then an AAD plan or implementation decision.

{task} is the original request. {previous} is the previous agent's report.

flowchart LR
  Task["{task}: original request"] --> Explorer["aad-explorer\nread-only discovery\nfiles, risks, verification hints"]
  Explorer --> Previous["{previous}: discovery report"]
  Previous --> Owner["aad-slice-owner\ndecide whole vs sliced"]
  Owner --> PlanOnly["If implementation NOT explicit:\ncompact AAD plan + next actions"]
  Owner --> Implement["If implementation explicit:\nproceed under AAD slice-owner rules"]

AAD owned-change chain

agents/aad-owned-change.chain.md is the main end-to-end implementation workflow.

The slice owner starts and finishes the workflow; reviewer and test auditor provide read-only gates.

flowchart TD
  Task["{task}: requested change"] --> Owner1["aad-slice-owner\nown change end-to-end\nworktree, implementation, verification"]
  Owner1 --> SliceReport["{previous}: slice report / context"]
  SliceReport --> Review["aad-reviewer\nread-only correctness + workflow review"]
  Review --> ReviewReport["{previous}: reviewer findings"]
  ReviewReport --> Audit["aad-test-auditor\nverification sufficiency audit"]
  Audit --> Feedback["{previous}: review + audit feedback"]
  Feedback --> Owner2["aad-slice-owner\nintegrate feedback\nfix current-goal issues\nrerun verification"]
  Owner2 --> Final["final AAD report\nno merge unless explicitly asked"]

AAD investigation chain

agents/aad-parallel-investigation.chain.md collects explorer, reviewer, and test-auditor perspectives. The current .chain.md format executes these sections in order; the name describes the support perspectives, not a parallel runtime fan-out.

Read-only support pipeline for shaping implementation boundaries and verification strategy.

flowchart LR
  Task["{task}: investigation request"] --> Explorer["aad-explorer\nread-only evidence"]
  Explorer --> Reviewer["aad-reviewer\nrisk shaping\ncorrectness hazards\nworkflow constraints"]
  Reviewer --> Auditor["aad-test-auditor\nminimum sufficient verification story\nlikely task targets"]
  Auditor --> Output["implementation boundaries\nverification recommendations\nno implementation"]

Hermes-style worker loop

These are standalone agents rather than checked-in .chain.md pipelines, but their prompts define a common orchestration loop.

Typical implementation, validation, and failure classification flow.

flowchart TD
  Hermes["Hermes / orchestrator"] --> Story["scoped story + test commands"]
  Story --> TDD["tdd-coder\nimplement minimal change\nrun targeted tests"]
  TDD --> Result{"PI_RESULT"}
  Result -- "PASS" --> Quinn["quinn-validator\nadversarial diff/spec review"]
  Quinn --> QResult{"QUINN_RESULT"}
  QResult -- "PASS" --> Done["ready for owner/user decision"]
  QResult -- "FAIL" --> Fix["send concrete findings back to implementation"]
  Fix --> TDD
  Result -- "FAIL or BLOCKED" --> Classifier["failure-classifier\nCODE_BUG / TEST_CONTRACT / TEST_BUG / INFRA / SCOPE_GAP / AGENT_LOOP / SECURITY_BLOCKER"]
  Classifier --> Next["NEXT_ACTION\nretry, adjust scope, escalate model, or ask human"]
  Next --> Hermes

Browser automation support

chrome-browser-agent chooses the safest browser mode for the task.

flowchart TD
  BrowserTask["browser automation task"] --> NeedsAuth{"Needs login, saved session, profile, passwords, extensions?"}
  NeedsAuth -- "no" --> Headless["browser-chrome-headless\ndisposable Chrome\npublic/simple/parallel checks"]
  NeedsAuth -- "yes" --> Headed["browser-chrome-headed\npersistent Chrome profile\nauth/session tasks only"]
  Headless --> CloseHeadless["close headless instance after use"]
  Headed --> PreserveProfile["do not inspect secrets\nclose only opened tabs"]

Capability matrix

Agent Primary role Write access by prompt/tools Context settings
aad-explorer Read-only discovery and evidence report Prompt says no file modification replace, project context on, skills on
aad-slice-owner Own one slice end-to-end; plan, implement, verify, integrate feedback Can edit/write replace, project context on, skills on
aad-reviewer Read-only correctness, verification, and workflow review Prompt says read-only replace, project context on, skills on
aad-test-auditor Read-only verification sufficiency audit Prompt says read-only except harmless verification commands replace, project context on, skills on
tdd-coder Scoped TDD implementation worker Can edit/write replace, project context on, inherited skills off; injects codex-tools
quinn-validator Adversarial diff/spec validator Read-only replace, project context on, inherited skills off; injects codex-tools
failure-classifier Classify failed task attempts and recommend next action Read-only unless explicitly asked for tiny diagnostic artifact replace, project context on, inherited skills off; injects codex-tools
chrome-browser-agent Browser automation via browser-chrome skill and MCP Browser side effects only as requested; protects profile secrets replace, project context on, inherited skills off; injects browser-chrome
