Pi Agent Pipelines

This page documents the executable agents and pi-subagents chain pipelines stored in agents/. Diagrams are rendered with Mermaid in the browser.

Agent inventory

AAD owner/support agents

aad-slice-owner owns scoped work. aad-explorer and aad-acceptance-auditor provide evidence and verification audit support.

AAD worker agents

aad-implementer implements scoped tasks and aad-failure-classifier classifies failed attempts.

Browser automation

chrome-browser-agent uses the browser-chrome skill and MCP browser servers, defaulting to disposable headless Chrome unless profile/auth state is explicitly needed.

AAD discovery-to-plan chain

agents/aad-discovery-plan.chain.md turns a request into evidence first, then an AAD plan or implementation decision.

{task} is the original request. {previous} is the previous agent's report.

flowchart LR
  Task["{task}: original request"] --> Explorer["aad-explorer\nread-only discovery\nfiles, risks, verification hints"]
  Explorer --> Previous["{previous}: discovery report"]
  Previous --> Owner["aad-slice-owner\ndecide whole vs sliced"]
  Owner --> PlanOnly["If implementation NOT explicit:\ncompact AAD plan + next actions"]
  Owner --> Implement["If implementation explicit:\nproceed under AAD slice-owner rules"]

AAD owned-change chain

agents/aad-owned-change.chain.md is the main end-to-end implementation workflow.

The slice owner starts and integrates the workflow; acceptance auditor provides both an audit pass and the final done-state gate.

flowchart TD
  Task["{task}: requested change"] --> Owner1["aad-slice-owner\nown change end-to-end\ntask package, draft PR, implementation dispatch"]
  Owner1 --> SliceReport["{previous}: slice report / context"]
  SliceReport --> Audit["aad-acceptance-auditor\nacceptance audit"]
  Audit --> Feedback["{previous}: audit feedback"]
  Feedback --> Owner2["aad-slice-owner\nintegrate feedback\nfix current-goal issues\nrerun verification"]
  Owner2 --> OwnerReport["final owner report\nno merge unless explicitly asked"]
  OwnerReport --> FinalAudit["aad-acceptance-auditor\nfinal acceptance gate"]
  FinalAudit --> Final["final acceptance verdict"]

AAD problem-investigation chain

agents/aad-problem-investigation.chain.md investigates a bug, failing test, suspicious behavior, or side finding before the owner decides whether it is a blocker, follow-up, false alarm, or scoped fix task.

Read-only support pipeline for producing a problem investigation packet. It does not implement a fix, though it may recommend a red/proving test.

flowchart LR
  Task["{task}: problem / failing behavior"] --> Explorer["aad-explorer\nevidence + reproduction\nrisk signals + scope"]
  Explorer --> Auditor["aad-acceptance-auditor\nacceptance verification story\nred/proving test recommendation"]
  Auditor --> Output["problem packet\nblocker/follow-up/false alarm\nrecommended next action"]

AAD worker loop

These are standalone agents rather than checked-in .chain.md pipelines, but their prompts define a common owner/orchestrator loop.

Typical implementation and failure classification flow. Acceptance remains with the owner and acceptance auditor.

flowchart TD
  Owner["AAD owner / orchestrator"] --> Story["scoped task + acceptance criteria + test commands"]
  Story --> Impl["aad-implementer\nred-green-refactor\nrun targeted checks"]
  Impl --> Result{"PI_RESULT"}
  Result -- "PASS" --> Done["implementation evidence\nready for owner/auditor decision"]
  Result -- "FAIL or BLOCKED" --> Classifier["aad-failure-classifier\nCODE_BUG / TEST_CONTRACT / TEST_BUG / INFRA / SCOPE_GAP / AGENT_LOOP / SECURITY_BLOCKER"]
  Classifier --> Next["NEXT_ACTION\nretry, adjust scope, escalate model, or ask human"]
  Next --> Owner

Browser automation support

chrome-browser-agent chooses the safest browser mode for the task.

flowchart TD
  BrowserTask["browser automation task"] --> NeedsAuth{"Needs login, saved session, profile, passwords, extensions?"}
  NeedsAuth -- "no" --> Headless["browser-chrome-headless\ndisposable Chrome\npublic/simple/parallel checks"]
  NeedsAuth -- "yes" --> Headed["browser-chrome-headed\npersistent Chrome profile\nauth/session tasks only"]
  Headless --> CloseHeadless["close headless instance after use"]
  Headed --> PreserveProfile["do not inspect secrets\nclose only opened tabs"]

Capability matrix

Agent Primary role Write access by prompt/tools Context settings
aad-explorer Read-only discovery and evidence report Prompt says no file modification replace, project context on, skills on
aad-slice-owner Own one slice end-to-end; coordinate planning, delegation, verification, and integration Can edit/write replace, project context on, skills on
aad-acceptance-auditor Read-only acceptance audit Prompt says read-only except harmless verification commands replace, project context on, skills on
aad-implementer Scoped implementation worker with TDD loop Can edit/write replace, project context on, inherited skills off; injects codex-tools
aad-failure-classifier Narrow failure evidence classifier Read-only for source/test/config; may write task-package report replace, project context on, inherited skills off; injects codex-tools, aad-task-package, aad-failure-classification
chrome-browser-agent Browser automation via browser-chrome skill and MCP Browser side effects only as requested; protects profile secrets replace, project context on, inherited skills off; injects browser-chrome
