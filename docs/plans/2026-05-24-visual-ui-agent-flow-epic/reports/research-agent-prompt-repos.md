# Research: Open-source role-specific coding-agent prompt repos

## Summary

Curated repositories below contain inspectable agent prompts, mode definitions, rules, checklists, or browser-agent prompting patterns that are relevant to Pi AAD agents/skills for frontend/UI/design review, backend/API quality, DevOps/runtime readiness, acceptance/QA, and browser/screenshot visual review. Preference is given to GitHub repos with concrete Markdown/YAML/source prompt files rather than blog posts or high-level commentary.

> Note: this environment did not expose a web-search tool, so links/paths should be treated as a focused seed list to verify in GitHub before copying text. Favor borrowing patterns and structure; verify each repo's current `LICENSE` before reusing prompt wording.

## Patterns to borrow for Pi AAD agents/skills

1. **Use narrow role cards with activation criteria.** The strongest agent packs define when a frontend, backend, QA, DevOps, or UX agent should be invoked and what it must not own. This maps well to Pi AAD routing and avoids generic reviewers.
2. **Make visual/UI review screenshot-first.** Browser-agent repos show the importance of action/observation loops. Pi visual agents should require current screenshots for target viewports, identify the worst screenshot, and reject obvious clipping/overlap/low-quality composition even if DOM metrics pass.
3. **Separate implementation from audit.** BMAD, Roo/Cline-style modes, and SWE-agent loops all support a distinction between builder, architect, tester, and reviewer. Pi should keep implementation agents from self-approving acceptance/QA.
4. **Require evidence-bound findings.** QA and runtime readiness agents should report commands run, screenshots inspected, API responses/logs checked, and remaining gaps. Avoid unsupported "looks good" conclusions.
5. **Prefer composable skills over giant prompts.** Awesome Copilot and Continue-style rules suggest keeping framework standards, accessibility rules, API conventions, and deployment checks as small attachable instruction files.

## Sources dropped or lower priority

- Awesome-list-only repos for Claude Code/Cursor agents — useful for discovery, but excluded unless they contain inspectable prompt files directly.
- Blog posts about "best AI coding prompts" — excluded because the task asks for borrowable repositories, not commentary.
- Leaked system-prompt collections — excluded due to unclear provenance/licensing and poor fit for open-source reuse.
- Framework-specific `.cursorrules` dumps — lower priority unless a file contains an explicit frontend/backend/QA checklist with a clear license; many are duplicated or unmaintained.
